# LKPD-5

C. MISI 1 — Memahami Issue
1. Apa fungsi GitHub Issue?
GitHub Issue berfungsi untuk mencatat dan mengatur pekerjaan atau masalah yang harus dikerjakan dalam sebuah proyek.
2. Mengapa pekerjaan sebaiknya dicatat sebagai Issue?
Agar setiap pekerjaan jelas, dapat dibagi kepada anggota tim, dan dapat diketahui status serta penanggung jawabnya.
3. Apa perbedaan Issue dengan Commit?
Issue digunakan untuk mencatat tugas yang harus dikerjakan, sedangkan Commit digunakan untuk mencatat perubahan yang sudah dibuat pada kode.

Q. SIMULASI MASALAH
Kasus 1:
Andi dan Budi sama-sama mengerjakan halaman Profil. Apa yang seharusnya dilakukan?
Jawaban:
Mereka harus menentukan satu orang sebagai penanggung jawab melalui Assignee agar pekerjaan tidak tumpang tindih. Jika diperlukan, pembagian tugas dapat dilakukan dengan jelas melalui Issue dan Branch.
Kasus 2:
Satu Issue sudah dikerjakan tetapi belum ada Pull Request. Apakah Issue sebaiknya langsung dianggap selesai? Mengapa?
Jawaban:
Tidak. Issue belum sebaiknya dianggap selesai karena hasil pekerjaan masih harus melalui Pull Request, Code Review, dan Merge sebelum Issue ditutup.
Kasus 3:
Budi memiliki 20 commit, sedangkan Andi hanya 5 commit. Apakah otomatis Budi memiliki kontribusi lebih besar?
Jawaban:
Tidak otomatis. Jumlah commit tidak selalu menunjukkan besar kecilnya kontribusi. Yang perlu dilihat adalah perubahan dan pekerjaan yang benar-benar dilakukan.

REFLEKSI TIM

Sebelum menggunakan GitHub Issues:
Pembagian tugas masih kurang teratur dan sulit mengetahui tugas masing-masing anggota.

Setelah menggunakan GitHub Issues:
Pembagian tugas menjadi lebih jelas karena setiap pekerjaan dicatat sebagai Issue dan memiliki anggota yang bertanggung jawab.

Hal yang paling membantu:
Fitur Issue, Label, dan Assignee karena memudahkan kami dalam membagi dan memantau pekerjaan.

Hal yang masih membingungkan:
Kami masih perlu memahami lebih baik proses Pull Request, Code Review, dan Merge.

Perbaikan workflow tim:
Kami akan membuat pembagian tugas yang lebih jelas, melakukan komunikasi sebelum coding, menggunakan branch sesuai tugas, dan selalu melakukan review sebelum kode di-merge ke branch main.
